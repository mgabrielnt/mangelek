# Pricing page — compact revision

## Why this revision

The first version repeated the Home landing-page treatment: large editorial
headlines, feature cards, planned add-on cards, and a large marketing footer.
The user requested a professional, less AI-looking, single-page pricing layout.

## Research and resulting choices

Reviewed official pages on 14 September 2026:

- [Framer](https://www.framer.com/pricing): places plan name, price, billing
  context, core inclusions and CTA together; separates optional add-on costs.
- [Ghost](https://ghost.org/pricing/): keeps billing selection, core plan
  features and signup actions near each other.
- [Basecamp](https://basecamp.com/pricing): uses direct plan descriptions,
  explicit allocations and clear signup actions.

These are observed layout/content patterns, not evidence of conversion gains.
For Mangelek, adapt their information hierarchy to one package; do not copy
multi-tier comparisons, prices, guarantees, customer counts or free trials.

## Result

One `/pricing` route, one package card, one compact FAQ area, one small footer.
The card groups plan/billing/CTA, eight feature inclusions, capacity information,
and a single domain-cost row. No oversized hero, gradients, serif slogans,
repeated feature cards, sales badges, decorative motion or giant footer.
Planned storage and AI add-ons are mentioned only in the FAQ.
Mobile content flows vertically with normal scrolling; no clipped fixed height.

## Commercial status and configuration

No price or usage quota has been approved. Do not use old handoff examples.
`src/data/pricing/plan.ts` holds approved billing totals in integer IDR.
Empty options show a direct pending-price message. One option has no selector;
two options expose native monthly/yearly radios with a live price announcement.
A yearly amount is the full annual bill, not a monthly equivalent.
`src/data/pricing/features.ts` holds inclusions, approved quotas and domain costs.
`src/data/pricing/faq.ts` holds billing/availability explanations.
Before launch, update these together with tax, renewal, cancellation and checkout.
CTA currently opens the existing Home theme gallery; it does not take payment.
Front-end quotas must match backend entitlements and enforcement.

## Technical notes

Existing Home header is reused; Home itself is not redesigned by this revision.
Pricing content is server rendered; only billing selection needs React state.
FAQ uses native details/summary. No runtime dependencies are added.
CSS is scoped to Pricing and respects reduced motion.
Source files remain below 70 lines.
